## Problem Statement

The telecom industry experiences **high customer churn**, making it crucial to understand why customers leave. This project analyses customer **demographics, services, billing details and account information** to find the patterns and factors that influence churn, and then builds a model that predicts churn for individual customers. The goal is to produce **actionable insights** that improve customer retention.

## Objectives

- Identify the overall **churn rate** and compare it with active customers.
- Analyse how **demographics, services, billing and account** details influence churn.
- Uncover important **patterns, correlations and trends** through EDA.
- Build and evaluate a **machine learning model** that predicts churn.
- Provide **actionable insights** to improve retention strategies.

## Dataset

- **Source:** IBM Telco Customer Churn dataset (`WA_Fn-UseC_-Telco-Customer-Churn.csv`)
- **Size:** about 7,000 customers (the test set holds 1,409 customers, a 20% split)
- **Target:** `Churn` (Yes/No). About 26.5% of customers churned, so the classes are imbalanced.

| Column | Description |
|---|---|
| `customerID` | Unique identifier assigned to each customer |
| `gender` | Customer's gender (Male/Female) |
| `SeniorCitizen` | Whether the customer is a senior citizen (0 = No, 1 = Yes) |
| `Partner` | Whether the customer has a partner (Yes/No) |
| `Dependents` | Whether the customer has dependents (Yes/No) |
| `tenure` | Number of months the customer has stayed with the company |
| `PhoneService` | Whether the customer has phone service (Yes/No) |
| `MultipleLines` | Availability of multiple phone lines |
| `InternetService` | Type of internet service (DSL / Fiber optic / No) |
| `OnlineSecurity` | Online security service status |
| `OnlineBackup` | Online backup service status |
| `DeviceProtection` | Device protection plan status |
| `TechSupport` | Technical support service status |
| `StreamingTV` | Access to streaming TV service |
| `StreamingMovies` | Access to streaming movie service |
| `Contract` | Contract type (Month-to-month / One year / Two year) |
| `PaperlessBilling` | Whether the customer uses paperless billing (Yes/No) |
| `PaymentMethod` | Customer's mode of payment |
| `MonthlyCharges` | Monthly charges billed to the customer |
| `TotalCharges` | Total charges incurred by the customer |
| `Churn` | Whether the customer discontinued the service (Yes/No) |

## Data Cleaning

- `TotalCharges` was stored as text because it contained blank strings (new customers with no billing history yet). Blanks were converted to missing values and the column was cast to a numeric type.
- Since the distribution of total charges is skewed, the missing values were filled with the **median**.
- Duplicate rows and null counts were checked.

## Churn Prediction Model

### Approach

1. **Split first:** an 80/20 stratified train/test split, done before any preprocessing so the test set never influences training (no data leakage).
2. **Preprocessing pipeline:** numeric columns are median-imputed and scaled; categorical columns are one-hot encoded.
3. **Class imbalance:** handled with `class_weight="balanced"`.
4. **Model comparison:** Logistic Regression, Random Forest and Histogram Gradient Boosting, compared with 5-fold stratified cross-validation on ROC-AUC (training set only).
5. **Final evaluation:** the best model is evaluated once on the held-out test set with ROC-AUC, precision, recall and a confusion matrix.
6. **Interpretation:** permutation importance shows which features drive churn.
7. **Persistence:** the whole pipeline (preprocessing and model) is saved with joblib.

## Results

![Confusion matrix and ROC curve](images/evaluation.png)

**Confusion matrix (test set, 1,409 customers, threshold 0.5)**

| | Predicted Stay | Predicted Churn |
|---|---|---|
| **Actual Stay** | 747 | 288 |
| **Actual Churn** | 81 | 293 |

| Metric | Value |
|---|---|
| ROC-AUC | **0.84** |
| Recall (churn) | **~78%** (293 of 374 churners caught) |
| Precision (churn) | **~50%** (293 of 581 flagged customers) |
| Accuracy | ~74% |

### Interpretation

- A ROC-AUC of 0.84 means the model ranks a random churner above a random non-churner about 84% of the time.
- Because churners are the minority class, the model is tuned to **catch churners (high recall)** at the cost of some false alarms (lower precision). A wasted retention offer is usually cheaper than a lost customer.
- The decision threshold can be moved to fit the business goal: a lower threshold catches more churners with more false alarms, a higher one does the opposite.
- Accuracy alone is misleading with imbalanced classes, which is why recall, precision and ROC-AUC are reported.

### Feature importance

Permutation importance on the test set (the drop in ROC-AUC when a feature is shuffled) is printed by `churn_model.py`. Services such as `StreamingMovies`, `OnlineSecurity` and `TechSupport` contribute to the prediction, alongside the contract, tenure and charge features highlighted in the EDA.

## Using the Saved Model

```python
import joblib
import pandas as pd

model = joblib.load("churn_model.joblib")

new_customers = pd.read_csv("new_customers.csv")   # same columns as the training data, without Churn
new_customers["TotalCharges"] = pd.to_numeric(new_customers["TotalCharges"], errors="coerce")
new_customers = new_customers.drop(columns=["customerID"], errors="ignore")

churn_probability = model.predict_proba(new_customers)[:, 1]
```

## Key Takeaways

- **Contract type** is a major factor: month-to-month customers churn far more than customers on one- or two-year contracts.
- **Fiber optic** customers and customers paying by **electronic check** churn the most.
- Customers **without tech support** or **without dependents** are more likely to leave.
- **Early tenure** is a risk period, so onboarding and early retention offers matter.
- The model catches about 78% of churners, which makes it useful for prioritising retention outreach.
